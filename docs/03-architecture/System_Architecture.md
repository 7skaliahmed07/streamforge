# Purpose

This document describes the internal architecture of StreamForge.

It explains how application services, databases, streaming components, processing systems, and analytics systems work together.

---

# Architecture Layers

StreamForge follows a layered architecture approach.

The main layers are:

1. Presentation Layer

2. Application Layer

3. Data Storage Layer

4. Streaming Layer

5. Processing Layer

6. Analytics Layer

7. Infrastructure Layer

---

# Presentation Layer

## React Frontend

Purpose:

Provides the user interface for interacting with the platform.

Responsibilities:

- Display business information.
- Provide user interactions.
- Consume backend APIs.
- Display analytical results.

Communication:

The frontend communicates with the backend through REST APIs.

---

# Application Layer

## Node.js Express Backend

Purpose:

Handles business logic and application operations.

Responsibilities:

- Process user requests.
- Validate input data.
- Apply business rules.
- Communicate with databases.
- Publish business events.

Main Modules:

## Customer Module

Handles customer related operations.

## Product Module

Handles product related operations.

## Order Module

Handles order creation and processing.

## Event Module

Publishes business events to Kafka.

---

# Data Storage Layer

## Operational Database

Technology:

PostgreSQL

Purpose:

Stores transactional application data.

Main Entities:

- Customers
- Products
- Orders
- Payments
- Inventory

The operational database is optimized for application transactions.

---

# Streaming Layer

## Apache Kafka

Purpose:

Provides real time event communication between services.

Kafka receives events generated by the backend application.

Example Topics:

## orders

Contains order related events.

Example:

Order created.

---

## payments

Contains payment related events.

Example:

Payment completed.

---

## inventory

Contains inventory related events.

Example:

Stock updated.

---

# Processing Layer

## Apache Spark Structured Streaming

Purpose:

Processes real time events from Kafka.

Responsibilities:

- Read streaming events.
- Validate data.
- Clean information.
- Transform data.
- Create analytical datasets.

Spark sends processed data to the warehouse.

---

# Communication Flow

The complete system communication flow:

1. User interacts with React application.

2. React sends request to Node.js API.

3. Backend validates request.

4. Backend stores transactional data in PostgreSQL.

5. Backend publishes event to Kafka.

6. Spark consumes Kafka events.

7. Spark processes and transforms data.

8. Processed data is stored in the warehouse.

9. Power BI reads warehouse data.

10. Business users view insights.

# Design Principles

StreamForge follows these principles:

- Separation of responsibilities.
- Scalable architecture.
- Reliable data processing.
- Clear communication between components.
- Maintainable code structure.
- Observable system behavior.
